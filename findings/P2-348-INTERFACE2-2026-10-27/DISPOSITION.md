## Remaining C4: two incompatible schema proposals, not an admitted decoder

**Runtime-learned option(a) is not accepted.** Recording an unknown version and
trusting the first value in a trial is not independent qualification of its class/
opcode/version/encoding/fields. Version must be qualified at the relevant event
type, not learned once for a whole class containing different event types.
Microsoft's [FileIo parent-class EventVersion(2)](https://learn.microsoft.com/en-us/windows/win32/etw/fileio)
is not evidence that all current child-event payloads are v2; its
[ReadWrite page](https://learn.microsoft.com/en-us/windows/win32/etw/fileio-readwrite)
defines semantic fields, not an actual trace from this host. Header
[PointerSize](https://learn.microsoft.com/en-us/windows/win32/etw/eventtrace-header)
is likewise not a substitute for validating the actual event encoding. Zero/missing
fields and unsupported layouts remain STOP, not values filled from assumptions.

**The proposed GUID-disagreement rule rejects an already documented valid export
shape.** [Current native method §2.3](https://github.com/mmsanders/Digital-Tape/blob/7126ca63f6fdd4251337157171d141a73c5a9bed/docs/WP14-NATIVE-CAPTURE.md#L171)
records actual Windows11 build26200 classic kernel exports: System/Provider is
the kernel-session GUID9e814aad…, while ExtendedTracingInfo/EventGuid is the
event CLASS. Those different GUIDs are intentional. The established rule uses
EventGuid as authoritative when present; a Provider naming a DIFFERENT KNOWN
CLASS is a conflict. Comparing every kernel-session Provider to EventGuid and
stopping on all differences cannot be called a supported current native contract.

The same published method records actual FileIo ReadWrite v3 and Thread v3 as
ProcessingErrorData15005/raw EventPayload, with specific lengths/pointer rules.
609 deliberately excludes all raw payloads, which is a valid conservative STOP,
but no qualified alternative named-field export for the required records has been
substantiated. Do not infer it from the OS, one WPR keyword or MOF names. No old
trace was rescanned or checker replayed to establish this: the published accepted
shape/disposition is sufficient. This does not prove every future export impossible.

Thus neither option(a) nor the still-unspecified fixed actual schema reader is
cleared for a positive route1 result. Any correct conservative unknown/raw STOP
must remain a STOP; it is not missing-lineage proof or Windows-method qualification.
