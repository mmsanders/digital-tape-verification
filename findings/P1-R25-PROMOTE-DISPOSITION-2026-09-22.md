## Published adapter contract

`tests/promote_draft8/ADAPTER.md` requires:

- after setup mount, clear the callback trace;
- retain the complete callback trace generated by all `tape_promote` calls;
- each callback event is `read|write|flush`;
- reads/writes include LBA and count;
- **do not filter callbacks**;
- setup/teardown mount I/O is deliberately excluded.

The verifier uses callback destinations and ordering as normative evidence for
the uninterrupted FRESH paths, and requires zero writes on refusal / no-op
paths. Complete callback capture is therefore part of the evidence boundary,
not diagnostic decoration.

## Exact adapter defect

At exact product head, `tests/promote_adapter/wp_promote_probe.c` implements
`mem_read` and `mem_write` in this order:

1. compute `end = lba + count`;
2. if `end > block_count`, return `-1` immediately;
3. only after the range check succeeds, call `trace_extent(...)`.

Therefore an out-of-range block callback **is invoked by the product device
interface but is omitted from the retained observation**.

This is filtering. It violates the published mechanical adapter contract.

The omission is material. A faulty implementation could, for example, issue an
out-of-range write during `tape_promote`, receive the callback's `-1`,
ignore that error, and still later return the expected public result / produce
the expected retained metadata. The verifier would then see neither the invalid
write destination nor the fact that the write callback occurred. The same
capture defect exists for out-of-range reads.

Verification cannot determine from the present artifact whether such omitted
callbacks occurred, because the adapter intentionally leaves no record of them.
Implementation blindness forbids resolving that uncertainty by inspecting
engine internals.

### What is *not* defective

The rest of the audited evidence plumbing is mechanically suitable:

- Software's wrapper delegates case generation/verdicting to the unchanged
  verifier-owned `runner.py`.
- The wrapper authenticates the imported verifier tree before execution.
- The probe mounts Side A only for `PR-DEGRADED` and Side B otherwise, exactly
  per contract.
- Every retained `tape_promote` call uses `block_budget=64`.
- The adapter records mount, every promote result/`more_work`, and unmount.
- Successful in-range reads/writes and every flush are retained in order during
  the promote trace.
- Event-array overflow sets an adapter failure.
- Call-array saturation / nonterminating continuation also forces adapter
  failure.
- Setup/teardown callbacks are excluded intentionally, as the verifier contract
  directs.
- The verifier runner retains raw stdout, parsed observation, adapter exit,
  per-case input/output VO08 and a hash-bound manifest.
