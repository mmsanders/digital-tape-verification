# WP-06 R44 sequential adapter contract

The Product adapter is a separate executable. Run exactly the cases in `oracle.cases()` against a fresh block file per case at the **issued** Product main `788cb765493096a076603e5ad4ac6e2dea47a7a9` (engine tree `054d27ab6e3e72f61118ff7d99e19e48741d05b2`), or label a later source explicitly. The adapter must not import the oracle or manufacture expected results. Emit one JSON object per case as JSONL. Record the real `tape_*` result and public info fields, every `dev_read`, `dev_write`, `dev_flush` invocation in order (including failed callbacks), and direct raw block reads *outside* the engine at the named snapshots. `step` partitions a call, `ordinal` is a monotonically increasing event number per case, `phase` is the observed mount phase for a write, `lba` is integer; don't count observation reads as engine callbacks.

Object: `schema: "wp06-r44-v1"`, `case`, `block_count`, `calls: [{step,fn,result,...}]`, `events: [{step,op,ordinal,lba?,phase?,result?}]`, `snapshots: {name: {primary: hex512, mirror: hex512, A0: {header: hex512, entries: hex(12*entry_count)}, ...}}`. For malformed index headers, `entries` is the bounded prefix specified by the fixture's header count; zero entries when the header is zero. Capture snapshots even if the engine refuses. For repair cases use `before`, `after_mount`, `after_retry`; for degraded cases `before`, and on reset `after_reset`, `after_remount`; round-trip cases `after_format`, `after_remount`; refusal cases `before`, `after_mount`. A failed repair callback may or may not leave its target durable; preserve the real file snapshot. Retry with callbacks healthy, unmounting the first instance first. Never reuse an instance across cases.

Step names are fixed in `oracle.check()`: `mount`, `retry`, `probe`, `exercise`, `remount`, `switch`, `format`, `mount1`, `commit`, `unmount`, `mount2`. Use the case family/variant to initialize media: both indices individually valid except specified degradation/refusal; corrupt or stale exactly the named partner; stage mismatch or bad A in refusal cases; Side A nonempty and B absent/equal-divergent for degraded cases. For round trips format a fresh device, mount B, arm/feed/service until owed frames clear, commit, unmount/remount; `max-entries` must exercise 4096 live entries and 96 entry-array blocks before the header. Record actual accepted frame count/selected B slot and raw output. A commit with accepted frames has chunk writes during `service`, **not** during `commit`. The adapter should record fixture-construction SHA-256 and its source/build command alongside the JSONL; `runner.py` binds its own oracle, plan, input digest, Product SHA/tree and adapter-source digest in a non-overwriting manifest.

The oracle does not grant Product acceptance. A synthetic self-test tests parser/red-control sensitivity only. A Product result needs the real adapter, committed immutable Product source identity and retained unabridged JSONL plus manifest. Unknown API visibility, including inability to report `free_next`, must be returned as a concrete blocker rather than guessed from an adapter's internal state.
